
最简单的 CPU，就是一个会读指令，有计算单元，操作寄存器和内存中的值的这么一个单元。但是丧心病狂的人类为了让它跑得快一点，产生了无数奇思妙想，导致现代 CPU 的结构、组成极其复杂。我们尽量讲清楚一点。

## pipeline

最开始，core 是单周期的，每个指令都耗费一个周期执行，并且在这个周期中，这条指令完整占用 core 的所有单元（哪怕没有在计算！）。

这样的问题在于，指令花费的时间不一定一样，每个指令都消耗一个周期，那么周期耗时只能跟最长的对齐，导致执行耗时短的指令时有浪费。

所以一个优化就是，我们把不同长度的指令拆成若干周期来执行，长的指令对应更多的周期，这样就不会有很多时间上的 core 空转浪费。

但是另一个维度，也就是空间维度上的浪费还没有解决。指令在执行的不同阶段，大概率不会使用 core 上的所有算力，这就导致每一时刻总有单元处于闲置状态。

所以另一个优化就是，我们发现每一条指令几乎总是按一定的顺序使用 core 的某些单元（比如，fetch, decode, execute, mem, write-back），我们把一条周期拆成这几个阶段，然后用工厂流水线的方式来执行，这样就可以解决空间上的浪费。

然而，使用 pipeline 之后，分支就成了让我们头疼的大问题。遇到 if 语句如果 stall 会导致流水线暂停，如果随便猜一个继续执行，猜对了很好，猜错了会导致之前运算全部失效，需要清空流水线重来。

因此，怎么猜对很重要。core 里有一个分支预测单元专门负责这件事。

pipeline 方向上的优化，本质上是把调控单元不断细化。从以整个 core、整个 inst 为单位调度，一步步细分，这样能减少浪费。

这些优化都是通过减小周期长度来加速的。

## ILP

Instruction level parallelism，分成 superscalar 和 out-of-order 两部分。

观察程序员写的代码，我们发现，虽然理论上代码需要从前到后一句一句严格按照顺序执行，但是很多时候其内部并没有这么严格的依赖关系。

有的时候，可能后面的指令需要的数据已经就绪，但是当前要执行的指令还没准备好。那与其让 core 等待，不如先执行后面的指令。这就是 out-of-order，深度维度的 ILP。

有的时候，可能有这么几条指令彼此没有依赖关系，可以同时执行。那与其一个个顺序执行，不如我们多增加一些 fetch 和 execute 单元，然后同时发射这几条指令同时执行。这就是 superscalar，宽度维度的 ILP。

这些优化都是通过减小 CPI 来加速的。

然而这些优化是有限的。通过实验发现，一个一般的程序最多有 2-3 的并行度。所以往一个 core 塞更多执行单元寄希望于 superscalar 是不现实的。

此外，有所谓 $\mu$-op 的概念，也就是说一个指令可能会被拆解成多条小指令执行。这样设计一方面是为了设计的灵活性，另一方面其实是跟多周期类似的思路，只不过拆成小指令有一个额外好处：我们可以利用 ILP。

## DLP

Data level parallelism，主要是 SIMD。

我们发现很多时候 core 都是通过循环在很多数据上执行相同的指令，那为什么不让它们一起执行？

所以我们引入新的计算单元，可以用一条指令控制多个数据的运算（本质上就是更宽的 ALU 罢了）。

另一种视角是，把 SIMD 看成被简化了的 multicore cpu。

这是通过减少指令数来加速的。

这有点像 GPU 的优化思路。

## TLP

一个程序访问内存时需要等待内存返回数据，这个时候 CPU 明明闲着却没事干。

虽然 out-of-order 和 superscalar 能缓解，但是我们想做到更好。为什么不同时准备多条指令流执行呢？如果有一条指令流开始等待，就执行别的没在等待的指令流。这样可以掩盖 latency。

这就是 SMT/Hyper-Thread，通过增加 context 单元，一个物理 core 伪装成多个（通常是 2 个）逻辑 core，交错执行两个线程的指令。

当然 TLP 也可以在 multicore 上做，所以严格来说我们这里介绍的只是 hyper-thread。

这也是 GPU 优化的思路。
## multicore

单个 core 是有上限的。计算单元再加，一个指令流也用不了那么多，反而会造成浪费。而加快周期会导致功耗增加。

所以 multicore 才是终点。这里就不归硬件管理了，更多是我们需要通过程序来控制多个 core 之间的协作。

## Memory

memory 其实是限制程序运行速度的重要因素，因为它的 latency 很高。

CPU 有多级 cache 来降低 latency，并且还会做 prefetch 来掩盖 latency。

不过多级 cache 还涉及到缓存一致性问题。
